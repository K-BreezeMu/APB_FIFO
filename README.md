## DUT 简介以及基本行为

这是一个**同步的先入先出 FIFO**，主要参数如下：

| 参数 | 取值 |
| --- | --- |
| 数据位宽 | 8 bits |
| FIFO 深度 | 16 entries |
| 总线位宽 | 32 bits |
| 寄存器数量 | 4 个 |

### APB3 总线协议

高级外设总线（APB3）是一种简单、低功耗的总线协议，专为外设访问而设计。它采用**两周期传输机制**：

- **SETUP 阶段（建立阶段）**：主机置位 `PSEL`，并设置地址（`PADDR`）、写/读控制（`PWRITE`）以及写数据（如果是写操作，则为 `PWDATA`）。`PENABLE` 保持低电平。
- **ACCESS 阶段（访问阶段）**：`PENABLE` 被置位。从机在就绪时通过 `PREADY` 进行响应，并提供读数据（如果是读操作，则为 `PRDATA`）或错误状态（`PSLVERR`）。
- **IDLE 阶段（空闲阶段）**：收到 `PREADY` 后，`PSEL` 和 `PENABLE` 恢复为低电平，从而完成本次传输。

## 调试记录（Debug Log）

### 问题 1：复位采样顺序竞争

**现象**：monitor 和 scoreboard 是同步的，monitor 检测到复位信号会立刻采样，导致采集复位结果时 scoreboard 比 refmodel 反应还快；其他情况因为 driver 有挂起等待 `psel` 等信号，所以没有问题。

**解决方法**：在复位信号之前加一个延时。

### 问题 2：read 到的 act 为 0

**现象**：读操作得到的实际值（act）为 0。

**解决方法**：driver 此处被误设置为**非阻塞赋值**。这是包里的值，不是 RTL 的值，导致需要等一个 clk 才能赋值，从而错过数据。改成阻塞赋值 `=` 即可。

## 验证计划（Verification Plan）

### 1. Reset 验证计划

| 测试项 | 结果 |
| --- | --- |
| 上电复位：开机就直接复位 | ✔ |
| Idle 阶段复位 | ✔ |
| Push/pop 后复位 | × |

**Bug 01**：
- **预期（Exp）**：Push data 后，应该不为空，count 为 1
- **实际（Act）**：push data 后 `empty` 为 1，count 为 0
- **分析**：很有可能是 DUT 本身在 push/pop 上有问题。

### 2. Push/Pop 验证计划

| 测试项 | 结果 |
| --- | --- |
| 进一出一验证 | ✔ |
| 连续进入后连续出来 | ✔ |
| 几乎全满几乎全空边界条件检测 | × |
| 上溢下溢检测 | × |
| 上溢下溢粘滞性检测 | × |
| Clear 功能检测 | ✔ |
| 几乎全满几乎全空阈值修改后的边界检测 | ✔ |
| Drop_on_full 检测 | × |
| 随机测试 | ✔ |

**Bug 02**：
- 发现 count 不计数，pop 出来只有 `0x00`，猜测是因为复位逻辑出问题、一直处于复位状态。
- 果然此处出了问题，进行修改。
- 修改后 Reset test 不再报错。

**BUG 03**：
- 在记到 15 的时候就已经显示为 `full`，而设计的 depth 是 16，估计是 DUT 写错了 depth。
- 但 `almost_full` 和 `almost_empty` 没有问题。

**BUG 04**：
- 从空 pop 出来的是 `a`，也没有触发下溢出，这是为什么？
- Push 到 17 成功触发了上溢。

**BUG 05**：
- Pop 后上溢信号归零，说明信号**粘滞性**不行。

**Drop_on_full 检测失败**：
- Actual 只有 0，`pslverr` 功能失效。
